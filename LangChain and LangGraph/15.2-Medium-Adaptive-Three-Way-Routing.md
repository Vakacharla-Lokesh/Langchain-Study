# Lab AdaptiveRAG-M1 — Three-Way Routing Graph

## Aim
Wire Lab AdaptiveRAG-E1's router into a full LangGraph that actually routes each question to a different execution path: direct generation, single-shot RAG, or your Lesson 12 multi-round agentic RAG agent — measuring total tokens/latency per tier to confirm cheaper paths are actually cheaper in practice.

## Agent Loop Shape
LangGraph with a 3-way conditional fan-out immediately after the entry point — no loop-back at this level (the "multi_step" branch's internal looping happens inside the agentic RAG sub-call it invokes).

## Pseudocode
```
class AdaptiveState(TypedDict):
    question: str
    route: str
    generation: str

def route_node(state):
    decision = router.invoke({"question": state["question"]})
    return {"route": decision.datasource}

def generate_direct(state):
    return {"generation": model.invoke(state["question"]).content}

def single_step_rag(state):
    docs = vectorstore.as_retriever(k=3).invoke(state["question"])
    context = "\n".join(d.page_content for d in docs)
    return {"generation": model.invoke(f"Context:\n{context}\nQ: {state['question']}").content}

def multi_step_rag(state):
    # invoke your Lesson 12 agentic RAG agent (create_react_agent with retriever + tavily tools)
    result = agentic_rag_agent.invoke({"messages": [HumanMessage(state["question"])]})
    return {"generation": result["messages"][-1].content}

builder = StateGraph(AdaptiveState)
builder.add_node("route", route_node)
builder.add_node("generate_direct", generate_direct)
builder.add_node("single_step_rag", single_step_rag)
builder.add_node("multi_step_rag", multi_step_rag)
builder.add_edge(START, "route")
builder.add_conditional_edges("route", lambda s: s["route"], {
    "no_retrieval": "generate_direct",
    "single_step": "single_step_rag",
    "multi_step": "multi_step_rag",
})
for node in ["generate_direct", "single_step_rag", "multi_step_rag"]:
    builder.add_edge(node, END)
```

## Hints & Suggestions
- Run your Lab AdaptiveRAG-E1 test set (or a similar 12-question set) through the full graph and, using LangSmith, log total tokens and latency **per route taken** — you should see a clear cost ordering: `no_retrieval` < `single_step` < `multi_step`. If that ordering doesn't hold, something's likely wrong with your routing (too many questions being pushed to the expensive path).
- Spot-check a few misrouted questions (if any) from your accuracy testing in Lab AdaptiveRAG-E1 — trace through the full graph to see what actually happens when a genuinely `multi_step` question gets misrouted to `single_step` (does it produce an incomplete answer? A wrong one? Note the failure mode).
- Compare this lab's total cost across your test set against running *every* question through the `multi_step` agentic RAG path unconditionally (i.e., no routing at all) — this delta is Adaptive RAG's entire value proposition, made concrete.

## Free APIs / Data to Use

## Further Reading
- Jeong et al., *Adaptive-RAG* — Section 4 (efficiency results: token/latency savings from routing simple queries away from the expensive multi-step pipeline without sacrificing accuracy on complex ones) — this is the exact experiment your lab's cost-measurement step reproduces at small scale.
