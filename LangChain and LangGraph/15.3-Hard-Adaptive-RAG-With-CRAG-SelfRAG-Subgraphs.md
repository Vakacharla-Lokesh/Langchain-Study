# Lab AdaptiveRAG-H1 — Adaptive RAG with CRAG/Self-RAG Sub-graphs

## Aim
Upgrade Lab AdaptiveRAG-M1's `multi_step` branch from a plain agentic RAG agent to your full **Self-RAG graph (Lab SelfRAG-H1)** or **CRAG graph (Lab CRAG-H1)**, compiled and embedded as a sub-graph node — demonstrating LangGraph's graph-composition capability and tying together nearly every pattern in this vault's RAG section into one system.

## Agent Loop Shape
Outer 3-way routing graph (Lab AdaptiveRAG-M1) with the `multi_step` branch now itself a fully cyclic, multi-checkpoint sub-graph (Self-RAG or CRAG) — the most architecturally deep graph in this vault.

## Pseudocode
```
# Assume self_rag_graph is your compiled graph from Lab SelfRAG-H1

def multi_step_rag_node(state):
    # Invoke the compiled Self-RAG sub-graph as a single node's worth of work
    sub_result = self_rag_graph.invoke({"question": state["question"]})
    return {"generation": sub_result["generation"]}

builder.add_node("multi_step_rag", multi_step_rag_node)
# rest of the AdaptiveRAG-M1 graph wiring stays the same

# Alternative, more "native" composition (if your LangGraph version supports it well):
# builder.add_node("multi_step_rag", self_rag_graph)   # compiled graphs can often be added directly as nodes
```

## Hints & Suggestions
- Start by confirming the sub-graph works correctly **standalone** (you already did this in Lab SelfRAG-H1 or CRAG-H1) before embedding it — debugging a broken sub-graph is much harder once it's nested inside the outer router.
- Decide deliberately: does the sub-graph need its own separate `thread_id`/checkpointer, or should it share the outer graph's state/config? For most cases, treating the sub-graph as a self-contained black box (own internal state, just passing question in / generation out) is simpler and matches this pseudocode — but note the tradeoff (the outer graph loses visibility into the sub-graph's internal retries) as part of your lab writeup.
- Run your full Lab AdaptiveRAG-E1 test set through this upgraded graph and compare answer quality on the genuinely `multi_step` questions against Lab AdaptiveRAG-M1's plain agentic RAG version — the hypothesis to test is whether Self-RAG/CRAG's extra grading actually produces measurably better (more grounded, more accurate) answers on the hardest tier, justifying the added cost specifically where it's routed to matter.
- This lab is a natural bridge toward the vault's original capstone ([[09-Capstone-Research-Assistant]]) — consider whether combining that capstone's checkpointing/human-in-the-loop patterns with this lab's adaptive-routing-into-self-correcting-RAG architecture would make sense as a personal follow-up project beyond this vault's scope.
