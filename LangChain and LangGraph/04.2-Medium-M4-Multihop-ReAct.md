# Lab M4 — Multi-hop ReAct Agent

## Aim
Build a 2-tool ReAct agent (fake `search(query)` + `calculator(expression)`) that answers a question requiring multiple chained lookups: search → extract a fact → search again → extract another fact → calculate. Print the full Thought/Action/Observation trace.

## Agent Loop Shape
Manual or `create_react_agent`-based loop (your choice at this point) — the focus is the *multi-hop* reasoning chain, not the loop implementation itself.

## Pseudocode
```
FAKE_DOCS = {
    "capital of france": "The capital of France is Paris.",
    "population of paris": "Paris has a population of approximately 2.1 million.",
    # keep this small (3-5 entries) so you can predict exactly what should be found
}

@tool
def search(query: str) -> str:
    """Search for factual information."""
    for key, val in FAKE_DOCS.items():
        if key in query.lower():
            return val
    return "No results found for that query."

@tool
def calculator(expression: str) -> str:
    """Evaluate a basic arithmetic expression."""
    return str(eval(expression))  # fine for a lab; never do this on untrusted input in production

agent = create_react_agent(model, tools=[search, calculator])
question = "What is the population of the capital of France, divided by 1000?"
result = agent.invoke({"messages": [HumanMessage(question)]})

for m in result["messages"]:
    print(m)   # walk the full trace
```

## Hints & Suggestions
- Keep `FAKE_DOCS` tiny and predictable — you should be able to say, before running it, exactly what the correct 2-hop trace looks like, so you can spot deviations immediately.
- Watch for the agent trying to do the division in its head instead of calling `calculator` — if it does, that's a prompting/tool-description issue worth noting, not a bug in your tools.
- Try a 3-hop version once this works (e.g., add a currency-conversion fake fact) to see where the agent's reliability starts degrading with chain length.

## Free APIs / Data to Use
- Stretch upgrade: replace `FAKE_DOCS` with real Wikipedia lookups via the free REST summary endpoint (`https://en.wikipedia.org/api/rest_v1/page/summary/{title}`, no key) so "search" returns real, if imperfect, extracted text — a taste of what Lesson 07's Tavily labs do properly.
