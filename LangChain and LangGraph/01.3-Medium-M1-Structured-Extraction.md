# Lab M1 — Structured Extraction with Fallbacks

## Aim
Extract a typed object `{sentiment, dishes_mentioned: list[str], rating_out_of_5}` from a messy restaurant review paragraph using `.with_structured_output()`, and add `.with_fallbacks()` to a second model in case the first fails to produce valid structured output.

## Agent Loop Shape
None — single structured call with a fallback chain, no tools, no looping.

## Pseudocode
```
class ReviewExtract(BaseModel):
    sentiment: Literal["positive", "negative", "mixed"]
    dishes_mentioned: list[str]
    rating_out_of_5: float

primary = model_a.with_structured_output(ReviewExtract)
backup  = model_b.with_structured_output(ReviewExtract)

extractor = primary.with_fallbacks([backup])

result = extractor.invoke(review_text)
# result is a validated ReviewExtract instance, not raw text
```

## Hints & Suggestions
- Deliberately feed it an ambiguous review ("food was okay but service ruined it") and check whether `sentiment` lands on "mixed" or gets forced into positive/negative — tells you how well the schema itself communicates intent to the model.
- To actually *test* the fallback path, temporarily point `primary` at a model/config that's likely to fail structured output (e.g., a much smaller/weaker model or a deliberately malformed schema) and confirm `backup` kicks in — don't just assume the fallback works, prove it triggers.
- `rating_out_of_5` as a float will sometimes get values like 4.5 out of a review that never states a number explicitly — decide if you want to constrain the schema (e.g., `Optional[float]`) to force the model to admit uncertainty instead of guessing.

## Free APIs / Data to Use
- No API needed — write or scrape a handful of real review-style paragraphs yourself, or pull sample text from any public dataset description page (e.g., Yelp's academic dataset page, read-only, no key needed to view sample text).
