# Lab H4 — Error-Recovery Agent (Self-Correction, Not Retry Code)

## Aim
Build a tool-using agent whose tool sometimes throws an exception (simulate a flaky external API). Prove the agent self-corrects — retries with different args, or asks the user for clarification — purely because the error was returned as a `ToolMessage`, with **no explicit retry/exception-handling logic of your own** beyond the "catch and return as string" pattern.

## Agent Loop Shape
Manual or LangGraph tool loop (reuse Lab M3's loop) — the point isn't a new loop shape, it's proving reasoning-driven recovery within it.

## Pseudocode
```
import random

@tool
def flaky_unit_converter(value: float, from_unit: str, to_unit: str) -> str:
    """Convert a value between units. Supports: km, miles, kg, lbs, celsius, fahrenheit."""
    if random.random() < 0.4:
        raise ValueError(f"Conversion service temporarily unavailable for {from_unit} -> {to_unit}, try again")
    conversions = {("km", "miles"): 0.621371, ("kg", "lbs"): 2.20462}
    key = (from_unit, to_unit)
    if key not in conversions:
        raise ValueError(f"Unsupported unit pair: {from_unit} -> {to_unit}. Supported: {list(conversions.keys())}")
    return f"{value * conversions[key]} {to_unit}"

# messages.append(ToolMessage(content=str(result), tool_call_id=call["id"]))
# ... call model again, let its next Thought decide what to do
```

## Hints & Suggestions
- Ask something that needs an unsupported conversion (e.g., "convert 10 celsius to kelvin") deliberately — a good agent should read the error's "Supported: [...]" hint and either give up cleanly or explain the limitation, not hallucinate a wrong answer.
- Run 10 trials of the *transient* failure case (the random 40% failure) and count how many times the agent retries successfully vs. gives up vs. hallucinates a result anyway — this success rate is your actual lab deliverable.
- Make the error messages genuinely informative (list supported units, suggest the fix) — this lab doubles as proof of Lesson 07's "docstring/error quality is a prompt-engineering problem" point, just applied to error strings instead of descriptions.
- Resist writing a `for attempt in range(3): try/except` wrapper around the tool call — that would be *you* retrying, not the agent reasoning about the failure. Keep the loop dumb; let the model's Thought carry the intelligence.
