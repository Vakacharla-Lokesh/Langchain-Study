# Lab H3 — Three-Tool Agent with Evaluation Set

## Aim
Build a 3-tool agent: Tavily search + one custom real API tool of your choice + a Python code-execution tool for complex calculations. Build a 5-question LangSmith evaluation dataset and score pass/fail.

## Agent Loop Shape
`create_react_agent` with 3 tools spanning real search, a real REST API, and sandboxed code execution — the most tool-diverse lab in the bank.

## Pseudocode
```
from langgraph.prebuilt import PythonREPLTool  # or wrap python_repl_ast tool

@tool
def get_weather(city: str) -> str:
    """Get current weather for a city using latitude/longitude lookup + Open-Meteo."""
    geo = requests.get(f"https://geocoding-api.open-meteo.com/v1/search?name={city}", timeout=5).json()
    lat, lon = geo["results"][0]["latitude"], geo["results"][0]["longitude"]
    weather = requests.get(
        f"https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&current=temperature_2m,weather_code",
        timeout=5
    ).json()
    return f"Current temp in {city}: {weather['current']['temperature_2m']}°C"

agent = create_react_agent(model, tools=[tavily_tool, get_weather, python_repl_tool])

eval_questions = [
    {"question": "What's the weather like in Tokyo right now?", "expect_substring": "°C"},
    {"question": "Search for the boiling point of nitrogen and convert it to Fahrenheit using code.", "expect_substring": "F"},
    # 3 more spanning each tool + combos
]

results = []
for item in eval_questions:
    out = agent.invoke({"messages": [HumanMessage(item["question"])]})
    final = out["messages"][-1].content
    passed = item["expect_substring"].lower() in final.lower()
    results.append({"question": item["question"], "passed": passed, "answer": final})

print(f"{sum(r['passed'] for r in results)}/{len(results)} passed")
```

## Hints & Suggestions
- Design your 5 questions to individually hit: Tavily-only, weather-tool-only, code-tool-only, Tavily+code combo, and all-three combo — this spread reveals which tool-selection boundary the agent struggles with most, if any.
- A pure substring check is a legitimate first version of "evaluation" — if you want to go further, look at LangSmith's `evaluate()` API and its LLM-as-judge evaluators to score answer *quality*, not just presence of a keyword.
- The Python code-execution tool is the riskiest one here — use a sandboxed/restricted version (`PythonREPLTool` from `langchain_experimental`, or a heavily restricted `eval` context) and never expose this pattern to untrusted user input outside a lab environment.
- Log every run to LangSmith and, at the end, manually open 2-3 of the traces to sanity check that a "passed" result was actually reasoned correctly and not a lucky keyword match.

## Free APIs / Data to Use
- **Tavily** — search.
- **Open-Meteo** (`https://open-meteo.com`) — free weather API, **no API key required**, includes a free geocoding endpoint too (`geocoding-api.open-meteo.com`) — genuinely one of the easiest real APIs to wire into a lab.
- Alternatives if you want variety: **Open Trivia DB** (`opentdb.com`, no key) for a trivia-lookup tool, **REST Countries** (`restcountries.com`, no key) for a country-facts tool, or **CoinGecko** (`api.coingecko.com`, no key for basic tier) for a live crypto-price tool.
