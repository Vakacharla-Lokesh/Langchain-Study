# Lab E3 — Few-Shot Formatting (Prompting Discipline, No Structured Output API)

## Aim
Force a model to always respond in a fixed JSON shape **using only few-shot examples in the prompt** — no `.with_structured_output()`, no output parser magic. Builds intuition for what structured-output helpers are actually saving you from.

## Agent Loop Shape
None — single call, pure prompting exercise.

## Pseudocode
```
examples = [
    {"input": "I love this laptop, fast and light",
     "output": '{"sentiment": "positive", "keywords": ["fast", "light"]}'},
    {"input": "Terrible battery life, disappointed",
     "output": '{"sentiment": "negative", "keywords": ["battery life"]}'},
    # 1-2 more examples
]

few_shot_prompt = FewShotPromptTemplate(
    examples=examples,
    example_prompt=PromptTemplate.from_template("Input: {input}\nOutput: {output}"),
    prefix="Classify sentiment and extract keywords as JSON, matching the exact format below.",
    suffix="Input: {input}\nOutput:",
    input_variables=["input"],
)

chain = few_shot_prompt | model | StrOutputParser()
raw = chain.invoke({"input": <new_text>})
parsed = json.loads(raw)   # will sometimes fail — that's the point
```

## Hints & Suggestions
- Run it 15-20 times with varied inputs and track how often `json.loads(raw)` throws — this failure rate *is* the lab's deliverable, and it's the exact number `.with_structured_output()` drives toward zero.
- Try reducing to 1 example vs. using 4 examples — compare the JSON-validity failure rate between the two to see how much few-shot count matters.
- Common failure mode: the model adds a trailing explanation after the JSON ("Output: {...} \n\nThis is because..."). Notice this pattern — it's *why* real pipelines don't rely on raw string parsing for anything production-facing.

## Free APIs / Data to Use
- None needed — write your own 15-20 test sentences, or pull real ones from a public review dataset sample.
