# Lab E2 — Parallel Chain (Multi-format Content Generator)

## Aim
Given one topic string, generate a tweet, a LinkedIn post, and a haiku — all three in a **single `.invoke()` call** using `RunnableParallel`. Confirms you understand concurrent Runnable composition, not just sequential piping.

## Agent Loop Shape
None — parallel fan-out, single call, no branching/looping.

## Pseudocode
```
parallel_chain = RunnableParallel(
    tweet = tweet_prompt | model | StrOutputParser(),
    linkedin = linkedin_prompt | model | StrOutputParser(),
    haiku = haiku_prompt | model | StrOutputParser(),
)

result = parallel_chain.invoke({"topic": <topic>})
# result = {"tweet": "...", "linkedin": "...", "haiku": "..."}
```

## Hints & Suggestions
- Time it: run the 3 prompts sequentially first (3 separate `.invoke()` calls, sum the latency), then run the `RunnableParallel` version — the wall-clock difference is the actual point of this lab.
- Each of the 3 sub-chains can have a completely different prompt template — that's the flexibility `RunnableParallel` gives you over a single shared prompt with format-switching logic.
- Stretch: add a 4th key that doesn't call an LLM at all — a plain Python function wrapped with `RunnableLambda` (e.g., a character-count of the topic) — to see that `RunnableParallel` mixes LLM and non-LLM Runnables freely.

## Free APIs / Data to Use
- None required — topics can be typed manually. If you want variety fast, pull a random Wikipedia article title via `https://en.wikipedia.org/api/rest_v1/page/random/summary` (no key) and use its title as the topic.
