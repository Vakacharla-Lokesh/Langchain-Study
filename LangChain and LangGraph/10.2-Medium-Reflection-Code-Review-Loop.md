# Lab Reflect-M1 — Code Review Loop (Reflection Applied to Code)

## Aim
Build a reflection loop that generates a small Python function from a spec, then has a critic pass actually **execute** the generated code against test cases (not just LLM-judge it) and feed real error output back as the critique, revising until tests pass or a round cap is hit.

## Agent Loop Shape
Cyclic LangGraph, same shape as Lab Reflect-E1, but the "reflect" step is now a **real code execution + test check**, not another LLM call — a grounded critic instead of an LLM-judged one.

## Pseudocode
```
class State(TypedDict):
    spec: str
    code: str
    test_output: str
    round: int

def generate(state):
    if state.get("test_output"):
        prompt = f"Fix this code based on the test failure.\nCode:\n{state['code']}\nError:\n{state['test_output']}"
    else:
        prompt = f"Write a Python function for: {state['spec']}. Only output the function code."
    return {"code": extract_code(model.invoke(prompt).content), "round": state.get("round", 0) + 1}

def run_tests(state):
    result = execute_in_sandbox(state["code"], test_cases_for(state["spec"]))
    return {"test_output": result.output_or_error}

def should_continue(state):
    if state["test_output"] == "ALL TESTS PASSED" or state["round"] >= 4:
        return "end"
    return "revise"

# generate -> run_tests -> conditional(should_continue) -> {revise: generate, end: END}
```

## Hints & Suggestions
- Use a genuinely sandboxed execution method (a subprocess with a timeout, or `langchain_experimental`'s `PythonREPLTool`) — never `exec()` untrusted model-generated code directly in your main process.
- Pick a spec with a real edge case the first generation is likely to miss (e.g., "a function that reverses a string, but must handle empty strings and None input") — this makes the reflection loop's value visible instead of trivially passing on round 1.
- Compare this grounded-critic version against Lab Reflect-E1's LLM-judged version: which converges faster / more reliably? A real test-execution critic tends to be far more reliable than an LLM guessing whether code "looks right" — this is worth explicitly noting as your lab's key finding.

## Free APIs / Data to Use
- None needed — local sandboxed execution only.
