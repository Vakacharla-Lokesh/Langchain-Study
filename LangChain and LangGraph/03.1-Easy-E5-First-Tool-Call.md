# Lab E5 — First Tool Call

## Aim
Define 2 simple tools (`add`, `multiply`), bind both to a model, ask a natural-language math question, and manually execute the single resulting tool call. No loop yet — just see the raw mechanics once.

## Agent Loop Shape
Single tool call, no loop — this lab exists to let you *see* `response.tool_calls` before you automate around it.

## Pseudocode
```
@tool
def add(a: float, b: float) -> float:
    """Add two numbers."""
    return a + b

@tool
def multiply(a: float, b: float) -> float:
    """Multiply two numbers."""
    return a * b

model_with_tools = model.bind_tools([add, multiply])
response = model_with_tools.invoke("What is 23 times 4?")

print(response.tool_calls)
# [{"name": "multiply", "args": {"a": 23, "b": 4}, "id": "call_xyz"}]

# Manually execute it:
call = response.tool_calls[0]
tool_map = {"add": add, "multiply": multiply}
result = tool_map[call["name"]].invoke(call["args"])
print(result)  # 92
```

## Hints & Suggestions
- Print `response.content` too, not just `.tool_calls` — notice it's often empty when the model chooses to call a tool instead of answering directly. This distinction matters a lot once you build the termination check in Lesson 04/06.
- Try a question that needs *both* tools ("add 5 and 3, then multiply the result by 2") and see whether the model requests one tool call at a time or emits both `tool_calls` in a single response (depends on provider/model support for parallel tool calls) — note what you observe.
- Try a completely unrelated question ("what's the capital of Japan?") and confirm `response.tool_calls` is empty — proves `bind_tools` doesn't force tool usage.

- None needed — pure arithmetic tools, no external calls.
