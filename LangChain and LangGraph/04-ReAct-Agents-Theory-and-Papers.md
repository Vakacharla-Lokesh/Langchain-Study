# 04 — ReAct Agents: Theory & Research Papers
> ⭐ This is the primary focus of the course. Spend disproportionate time here.

## Theory

### The core idea
ReAct = **Reason + Act**. Before ReAct, there were two separate lines of work:
1. **Chain-of-Thought (CoT) prompting** — model "thinks out loud" in free text before answering. Great for reasoning, but has no way to touch the outside world (no fresh info, no calculation, no side effects) — it can *hallucinate* facts fluently.
2. **Action-only agents** — model picks actions/tools based on the current state, but with little or no explicit reasoning trace. Effective at task completion but brittle and uninterpretable — hard to tell *why* a bad action was taken.

ReAct's contribution: **interleave the two.** The model produces a repeating cycle of:

```
Thought: <reasoning about what to do next, given everything so far>
Action: <tool name + args to call>
Observation: <the tool's result, appended by the system, not generated by the model>
... (repeat) ...
Thought: I now have enough information.
Final Answer: <answer to the user>
```

This loop is exactly the tool-calling loop from Lesson 03, with one addition: the model is explicitly prompted/trained to **verbalize a "Thought" before every Action**. That verbalization is not cosmetic — it's the mechanism by which:
- The model plans multi-step strategies instead of reacting greedily to only the last observation
- The model can catch its own errors mid-task ("Thought: that search returned nothing useful, let me rephrase the query")
- A human reading the trace can debug *why* the agent did what it did (huge for production debugging — this is exactly what LangSmith traces visualize, see Lesson 07)

### Why interleaving beats either alone (the paper's actual finding)
From Yao et al. (2022), tested primarily on HotpotQA (multi-hop QA) and FEVER (fact verification), plus decision-making tasks in ALFWorld and WebShop:
- **Reasoning-only (CoT) models hallucinate** — they reason fluently but drift from facts since they can't verify anything mid-generation.
- **Acting-only models act "blindly"** — good short-term task completion, poor at recovering from unexpected states because there's no explicit plan being tracked.
- **ReAct combines both**: reasoning traces help the model decide *which* action to take and *when to stop*, while actions ground the reasoning in real (retrieved/observed) information, checking hallucination.
- ReAct's advantage was most pronounced on tasks requiring **multi-step lookup + synthesis** — exactly the shape of most real agent tasks (search → read → search again → answer).

### The prompt shape (few-shot ReAct, pre-native-tool-calling era)
The original paper used **few-shot prompted text generation** — the model literally generated the string `"Thought: ... \nAction: search[query]\n"` as raw text, which the harness then parsed with string manipulation to actually call the tool, then appended `"Observation: ...\n"` and continued generating.

**Modern implementation difference (important):** today's LangChain/LangGraph ReAct agents don't parse `Action: tool[args]` strings — they use native tool-calling (Lesson 03) so the model emits a structured `tool_calls` object directly. The "Thought" now typically lives as free-text `content` the model produces *alongside or before* the structured tool call, rather than as a manually parsed action string. Functionally it's the same ReAct loop; the plumbing is just far less fragile because you're not regex-parsing model output anymore.

### Termination condition
The loop ends when the model, instead of emitting a tool call, emits a final natural-language answer with no `tool_calls`. This is the exact check used in the hand-rolled loop from Lesson 03's Medium lab, and it's what `create_react_agent` checks internally (Lesson 06).

### Relation to LangGraph
LangGraph didn't invent ReAct — it's the *runtime* that makes the ReAct loop (which is inherently a **cycle**, not a straight line) easy to express. LCEL chains (Lesson 01) are naturally acyclic (DAGs); ReAct needs "go back and call the model again" — a graph with a conditional edge back to itself. That's the whole reason `create_react_agent` in `langgraph.prebuilt` exists and why the ecosystem moved agent-building from LangChain's old `AgentExecutor` to LangGraph. Keep this bridge in mind going into Lesson 05/06.

## Important Points
- ReAct is a **prompting/interaction pattern**, not a specific piece of code — you can implement "a ReAct agent" by hand with a plain `while` loop (Lesson 03 Medium lab already did this), via LangChain's legacy `create_react_agent` (old-style, string-parsing based, deprecated path), or via **LangGraph's `create_react_agent` prebuilt** (modern, native tool-calling based) — know which one a tutorial is showing you.
- The "Thought" step is what separates ReAct from plain tool-calling loops. A tool-calling loop with zero visible reasoning between calls is *not* ReAct, it's just "function calling in a loop."
- ReAct is not the only agent architecture — know it's one point in a design space that also includes **Plan-and-Execute** (plan all steps upfront, then execute — cheaper on tool calls, worse at adapting mid-task) and multi-agent orchestration patterns. You'll likely meet these later; for now ReAct is the baseline everything else is compared against.
- Failure modes to watch for in labs: **repetition loops** (model keeps calling the same tool with the same args because it "forgot" it already tried that — mitigated by good observation formatting and sometimes a max-iteration cap) and **premature termination** (model answers before it actually has enough Observations — mitigated by prompting it to be explicit about what's still unknown).
- Always set a **max iteration / max step limit** on any ReAct loop you build. An agent that's stuck reasoning-acting in a loop with no exit condition will burn tokens indefinitely — this is a real, not theoretical, failure mode.

## Research / Reference — Required Reading
1. **ReAct: Synergizing Reasoning and Acting in Language Models** — Yao, Zhao, Yu, Du, Shafran, Narasimhan, Cao. arXiv:2210.03629 (2022). *The* paper. Read at minimum: Abstract, Section 3 (methodology — the interleaving mechanism), and the HotpotQA/ALFWorld results tables.
2. **Chain-of-Thought Prompting Elicits Reasoning in Large Language Models** — Wei et al., arXiv:2201.11903 (2022). Prerequisite context: this is the "Reasoning" half ReAct builds on.
3. **(Optional, for depth) Reflexion: Language Agents with Verbal Reinforcement Learning** — Shinn et al., arXiv:2303.11366 (2023). A natural next step after ReAct — adds a self-critique/reflection memory across attempts. Good to skim once ReAct is solid; you'll likely see this pattern again as "reflection nodes" in more advanced LangGraph designs.
4. LangGraph docs — "Prebuilt ReAct Agent" page, to see the modern implementation side by side with the paper's original formulation.

## Hands-on Labs
- **Easy:** Take your hand-rolled tool-loop from Lesson 03's Medium lab and modify the system prompt so the model is *explicitly instructed* to output a `Thought:` line (as plain text content) before every tool call. Compare 5 runs with vs. without the instruction — does having a visible Thought change *which* tool gets picked on ambiguous queries?
- **Medium:** Build a 2-tool ReAct agent (a fake `search(query)` tool returning canned snippets from a small dict of "documents," and a `calculator(expression)` tool) that answers multi-hop questions like *"What is the population of the capital of France, divided by 1000?"* — requiring search → extract capital → search → extract population → calculate. Print the full Thought/Action/Observation trace.
- **Hard:** Build a ReAct agent with a deliberately **noisy/unreliable search tool** (returns irrelevant results ~30% of the time) and demonstrate the agent recovering — i.e., its Thought explicitly recognizes "this result doesn't answer the question" and it retries with a reformulated query, without you hardcoding retry logic. Add a hard cap of 6 iterations and handle graceful "I could not find a definitive answer" termination if the cap is hit.
