# Lab AdaptiveRAG-E1 — Query Complexity Router

## Aim
Build the router in isolation: a structured-output classifier that labels each incoming question as `no_retrieval` / `single_step` / `multi_step`, using few-shot examples to sharpen accuracy. Test it against a deliberately varied set of questions spanning all three tiers.

## Agent Loop Shape
None — single classification call, the foundational piece Lab AdaptiveRAG-M1 will route on.

## Pseudocode
```
class RouteQuery(BaseModel):
    datasource: Literal["no_retrieval", "single_step", "multi_step"]
    reason: str

router_prompt = ChatPromptTemplate.from_messages([
    ("system", """Classify the question's complexity for a RAG system.
    - no_retrieval: general knowledge, math, the model can answer directly
    - single_step: needs one lookup in our knowledge base, answerable from a single retrieval
    - multi_step: needs multiple chained lookups or reasoning across several pieces of information

    Examples:
    Q: "What is 12 * 8?" -> no_retrieval
    Q: "What is our company's return policy?" -> single_step
    Q: "How does our return policy differ between the shipping method used at checkout and the original order date?" -> multi_step
    """),
    ("human", "{question}")
])
router = router_prompt | model.with_structured_output(RouteQuery)

test_questions = [
    "What's the boiling point of water?",                                  # no_retrieval
    "What's our refund processing time?",                                   # single_step
    "Compare our refund policy for international vs domestic orders, and explain which applies to an order placed during a promotional period.",  # multi_step
]
for q in test_questions:
    print(router.invoke({"question": q}))
```

## Hints & Suggestions
- Build a test set of at least 12 questions (4 per tier) including a few deliberately ambiguous ones between tiers — measure routing accuracy against your own manually-assigned "correct" tier for each.
- If accuracy is weak on a specific tier, add 1-2 more few-shot examples targeting exactly that confusion (e.g., if `single_step` vs `multi_step` gets confused often, add a clearer contrasting pair) — this is standard few-shot debugging from Lesson 02, applied here.
- Note that this router is structurally almost identical to Lab SelfRAG-E1's 2-way retrieval gate — this one just adds a third tier distinguishing single-step from multi-step retrieval needs.
