# Lab SelfRAG-H1 — Full Self-RAG Graph

## Aim
Wire Labs SelfRAG-E1 (retrieval decision) and SelfRAG-M1 (hallucination grading) together with a document relevance grader (reuse Lab CRAG-E1's grader) and an answer-usefulness grader into the complete Self-RAG graph from Lesson 14's theory: retrieval decision → retrieve → grade relevance → generate → grade groundedness (loop back to regenerate if not grounded) → grade usefulness (loop back to retrieve if not useful) → end.

## Agent Loop Shape
LangGraph with **two distinct loop-back points** — the most structurally complex graph in this vault so far.

## Pseudocode
```
class SelfRAGState(TypedDict):
    question: str
    documents: list[str]
    generation: str
    retries: int

def decide_to_retrieve(state):
    decision = decision_maker.invoke(state["question"])
    return "retrieve" if decision.needs_retrieval else "generate_direct"

def retrieve(state): ...
def grade_relevance(state):
    relevant = [d for d in state["documents"] if grader.invoke(f"Q:{state['question']} Doc:{d}").grade == "correct"]
    return {"documents": relevant}

def generate(state):
    context = "\n".join(state["documents"]) if state["documents"] else "(no retrieval)"
    answer = model.invoke(f"Context:\n{context}\nQuestion: {state['question']}").content
    return {"generation": answer, "retries": state.get("retries", 0) + 1}

def grade_groundedness(state):
    if not state["documents"]:
        return "useful_check"  # nothing to be ungrounded against
    grade = hallucination_grader.invoke(f"Docs:{state['documents']} Answer:{state['generation']}")
    return "regenerate" if not grade.grounded and state["retries"] < 3 else "useful_check"

def grade_usefulness(state):
    grade = model.invoke(f"Does this answer usefully address the question?\nQ:{state['question']}\nA:{state['generation']}\nYES or NO").content
    return "end" if "YES" in grade.upper() or state["retries"] >= 3 else "retrieve_again"

# question -> conditional(decide_to_retrieve) -> {retrieve, generate_direct}
# retrieve -> grade_relevance -> generate
# generate_direct -> END
# generate -> conditional(grade_groundedness) -> {regenerate: generate, useful_check: continue}
# useful_check -> conditional(grade_usefulness) -> {end: END, retrieve_again: retrieve}
```

## Hints & Suggestions
- Build and test this incrementally: first confirm the "generate_direct" path works alone, then add retrieval, then add groundedness looping, then add usefulness looping — debugging all the branches at once is much harder than adding them one at a time.
- Both loop-back points need their own retry cap (this pseudocode reuses one shared `retries` counter for simplicity — consider whether separate counters for each loop type would give you more precise control, and note your reasoning either way).
- Deliberately engineer a test case that should trigger the groundedness loop (documents that are relevant but don't fully support a tempting-to-fabricate detail) and a separate case that should trigger the usefulness loop (a grounded but incomplete/unhelpful answer, e.g., documents that only partially answer a multi-part question) — verify both loops actually fire, not just the happy path.
- Compare total LLM calls for a simple question (should route through "generate_direct" with almost no overhead) versus a complex question that exercises both loops — this spread is the concrete cost of Self-RAG's added reliability, motivating Lesson 15's Adaptive RAG routing.

## Free APIs / Data to Use
- None strictly required — local vector store and fake/small document set is enough to exercise all branches deliberately.
