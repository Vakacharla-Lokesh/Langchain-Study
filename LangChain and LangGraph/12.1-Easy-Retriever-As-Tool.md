# Lab AgenticRAG-E1 — Retriever as a Tool

## Aim
Build a tiny local vector store (5-10 short documents), wrap it with `create_retriever_tool`, and hand it to a `create_react_agent` alongside no other tools. Confirm the agent calls the retriever when a question needs it and answers directly when it doesn't.

## Agent Loop Shape
`create_react_agent` with exactly 1 tool (the retriever) — the simplest possible agentic RAG setup.

## Pseudocode
```
docs = [
    Document(page_content="The company's return policy allows returns within 30 days with a receipt."),
    Document(page_content="Standard shipping takes 5-7 business days; express shipping takes 1-2 days."),
    # 3-8 more short, distinct facts
]

vectorstore = InMemoryVectorStore.from_documents(docs, embedding=embeddings_model)

retriever_tool = create_retriever_tool(
    vectorstore.as_retriever(k=3),
    name="search_policies",
    description="Search internal company policy documents about shipping, returns, and orders."
)

agent = create_react_agent(model, tools=[retriever_tool])

# Test 1: should trigger retrieval
r1 = agent.invoke({"messages": [HumanMessage("How long do I have to return something?")]})
# Test 2: should NOT trigger retrieval (out of scope / general knowledge)
r2 = agent.invoke({"messages": [HumanMessage("What's the capital of Italy?")]})
```

## Hints & Suggestions
- Print `r2`'s message trace and confirm the retriever tool was never called — a well-scoped tool description (per Lesson 03's rules) should keep the agent from searching irrelevant internal docs for a general-knowledge question.
- Try a question that's adjacent-but-not-covered by your documents (e.g., ask about a return policy detail you didn't include) — observe whether the agent honestly says it doesn't have that information, or hallucinates an answer despite an unhelpful retrieval. This gap is exactly what Lesson 13 (CRAG) exists to catch systematically.
- Vary `k` (number of retrieved chunks) and see how it affects both answer quality and how often irrelevant chunks show up in context for narrow questions.

## Free APIs / Data to Use
- None needed for the vector store itself — write your own small document set. Any embedding model your setup supports works (OpenAI embeddings, or a local sentence-transformers model if you want to avoid API calls for this step).
